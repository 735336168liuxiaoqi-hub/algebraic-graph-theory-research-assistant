# API配置与科研对话

日常使用：桌面切换“科研对话”→“模型设置”→选择协议、地址与模型→提供密钥→“保存并启用”。支持 Responses 和 Chat Completions 兼容接口；服务需能按提示返回本助手使用的 JSON 决策。

配置、保存和切换本身不联网；“获取模型列表”访问服务，“测试连接”发送诊断请求。工具计算在本机执行。密钥仅在本机提供，不放入问题文本、源码或公开配置。

## 桌面对话与模型选择

输入区上方可切换命名配置、模型和思考强度。模型ID可手填；列表需服务支持对应接口。思考强度以服务支持为准，“服务默认”不发送思考参数；未知第三方模型不会自动假定兼容。切换不重置预算，任务运行时不可切换。

插入图可绑定会话内的明确图版本；“先查看计划”便于核对步骤。条件不足时在同一对话补充。工具记录展示实际输入、状态、结果和附件；模型文字不等于已执行计算。图旁手动导出直接本地执行，不新增模型请求。

命名配置保存在模型设置目录的 `model.profiles.json`，只含公开设置。密钥缓存按地址、密钥环境变量名和认证开关隔离；关闭程序或“断开并清除密钥”会清除进程缓存。

## 预算、暂停与恢复

“预算与用量”显示累计消耗与限制，金额估计使用用户提供的单价。缺少函数时先澄清、评估，真实用户确认后才能开发[独立扩展](EXTENSIONS.md)。已有工具能组合完成时不新增包。

“停止”取消后续安排并停止计算子进程；已发送的模型请求仍可能等到返回或超时。成功步骤和历史保留；重启不自动重发请求。网络错误或暂停后由用户选择继续，不自动扩预算或重复请求。

## 推荐：从菜单开始

在源码项目中双击 **`start-assistant.cmd`**，或打开项目终端运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m graph_research connect
```

模型对话的接入步骤如下，选择5可直接跳过模型配置：

1. **配置模型**：填写协议、API地址、模型ID、是否需要密钥。此步不联网，不要求输入密钥。
2. **检查配置**：查看实际生效地址、模型和缺少项。此步只读本地配置，不消耗API用量。
3. **测试连接**：明确选择后，只发送一次短JSON请求，不发送科研记录或调用计算工具；可能产生少量服务商用量。
4. **独立使用科研助手**：在专门提示处隐藏输入密钥，随后可连续提问、补充需求、确认或拒绝开发，沿用按用户记忆和自动结果包。同一进程内不用每次重新输入密钥。
5. **无API工具模式**：按分类选择已有功能并填写参数，不需要模型、密钥或主agent。

安装wheel到其他环境后，用该环境的`python -m graph_research connect`，或`graph-research connect`打开菜单。

## 配置前准备什么

从所选服务商的API说明或控制台确认以下信息，不要把展示名称、网页地址或完整密钥混填：

| 项目 | 填写内容 |
| --- | --- |
| API基础地址 | 服务商提供的接口前缀，可能包含`/v1`或其他路径；没有统一适用于所有服务的地址 |
| 模型ID | API实际接受的模型标识，不一定等于页面上的名称 |
| 协议类型 | 服务是否接受`/responses`或`/chat/completions`格式 |
| API密钥 | 如服务要求认证，在隐藏输入提示处填写密钥本身，不加`Bearer `前缀 |

接口地址示意（`example.invalid`不能连接，不能原样当成真实服务地址）：

| 选择 | 基础地址示意 | 程序实际请求地址 |
| --- | --- | --- |
| Chat Completions | `https://example.invalid/v1` | `https://example.invalid/v1/chat/completions` |
| Responses | `https://example.invalid/v1` | `https://example.invalid/v1/responses` |
| 本机兼容服务 | `http://127.0.0.1:8000/v1` | 根据所选协议拼接结尾 |

如果粘贴的是完整请求地址，程序会识别并去掉重复结尾，再显示实际请求地址；结尾与所选协议冲突时拒绝保存。远程地址必须使用HTTPS；HTTP仅允许localhost或回环IP。本机服务直连，不通过环境变量中的代理转发。

当前认证方式为HTTP Bearer密钥，支持显式选择不需要认证的服务。需要额外查询参数、其他认证头、原生messages/generate格式或其他响应结构的接口，需要另行适配，不能仅凭“有API”就视为兼容。服务还需要能按提示返回完整JSON对象；只支持原生工具调用并不自动保证当前文本JSON协议可用。

## 也可分步运行命令

```powershell
# 中文配置向导，不联网、不保存密钥：
python -m graph_research model setup

# 只检查本地配置与依赖：
python -m graph_research model status

# 一次最小连接测试：需模型密钥，可能产生少量API用量。
# 没有密钥环境变量时，在本机交互终端专门提示处隐藏输入。
python -m graph_research model test

# 独立科研对话；用户标识留给你自行选择，不是密钥：
python -m graph_research standalone --user researcher_001
# 原chat命令也可使用，两者行为一致。
```

连接测试默认请求最多128个输出token，输入是固定的短测试消息。服务商是否报告用量、如何计费仍以其实际接口和账单为准。推理模型可能因这个上限太低而输出不完整，可以在了解用量后显式增大单次测试上限，不会自动增加或重试：

```powershell
python -m graph_research model test --max-output-tokens 512
```

一次测试通过只说明连接、响应格式与最小JSON决策可用，不表示所有科研任务或工具选择已经验收。随后可问一个有已知答案的问题，例如“计算P3的直径和邻接谱”，查看实际工具结果及打包记录。正式科研对话还会发送工具说明和对话上下文，用量会高于最小连接测试。

## 持续对话怎么操作

输入普通研究需求即可。同一会话可多次提问，每轮默认更新整次对话的结果包。需要操作时使用：

| 输入 | 行为 |
| --- | --- |
| `/导出` | 再导出当前对话，不调用模型 |
| `/查看` | 直接打开整理后的结果页，查看指标、表格、图形与下载文件；不调用模型或重新计算 |
| `/继续` | 恢复网络错误、取消等中断；已有成功计算保留 |
| `/确认 评估ID` | 阅读需求、预算和验收后，明确批准当前开发范围 |
| `/拒绝 评估ID` | 拒绝开发，不再调用模型，也不要求密钥 |
| `/退出` | 退出终端对话，保留会话记录和结果包 |

只有明确指定当前评估ID的确认命令才批准开发。普通回复“同意”等文字仍作为需求消息处理，不替代审批。

恢复已有会话：

```powershell
python -m graph_research chat --session "outputs/之前的会话目录"
```

旧的`ask`、`resume`命令继续可用，亦可隐藏输入密钥。多个独立进程之间不会保存输入过的密钥；同一`chat`进程会在内存中复用当前模型对象。不要把密钥当成研究问题输入，否则它会像普通用户消息一样进入会话记录。

## 配置保存在哪里

默认位置是当前操作系统账户主目录下`.graph_research/model.json`。这里仅保存地址、模型、协议及公开选项。已有合法公开配置更新时保留`.previous`；现有文件损坏或包含未知字段/密钥时，不自动复制或覆盖，需整理后重试，或选择一个新配置文件。

可在`model setup/status/test`与`chat`后传`--config 路径`，或者设置`RESEARCH_MODEL_CONFIG`。独立`ask`和`resume`使用`--model-config 路径`。用户标识用于科研记忆隔离，不是API登录认证，也不会自动切换服务商配置。

兼容原有环境变量方式，生效优先级是：

**当前终端环境变量 → 公开配置文件 → 默认公开选项。**

| 环境变量 | 含义 |
| --- | --- |
| `RESEARCH_BASE_URL` | API基础地址，覆盖文件中的地址 |
| `RESEARCH_MODEL` | 模型ID，覆盖文件中的模型 |
| `RESEARCH_API_MODE` | `responses`或`chat_completions`，覆盖文件中的协议 |
| `RESEARCH_API_KEY` | 默认密钥变量，仅在需要认证时使用 |
| `RESEARCH_MODEL_CONFIG` | 可选的公开配置文件位置 |

`check-model`现在也会给出离线诊断，但不会连接服务或证明密钥有效。切换服务商时请核对环境变量是否仍覆盖文件；建议不同服务使用不同密钥变量，或在新终端中隐藏输入对应密钥，避免误用旧密钥。

指定已有密钥环境变量的名称，不把值写入配置：

```powershell
python -m graph_research model setup --key-env MY_PROVIDER_API_KEY
```

若本机服务不要求认证，可在向导中选择`n`，或指定`--auth none`。此时即使环境中有默认API密钥，也不会将它发送给该服务。

## 常见问题提示

| 提示/状态 | 排查方法 |
| --- | --- |
| 尚未配置地址或模型 | 先运行`model setup`；不要仅填写密钥 |
| 密钥未提供 | 在本机交互终端隐藏输入，或设置所选密钥变量；不会读取桌面登录 |
| HTTP 401 | 检查密钥所属服务商、有效期及使用的环境变量 |
| HTTP 403 | 检查账户、模型权限或访问策略 |
| HTTP 404 | 检查实际请求地址、是否需要`/v1`、协议与模型ID |
| HTTP 400 | 检查协议、JSON模式和该模型接受的输出上限字段 |
| HTTP 429 | 查看频率/配额，稍后手工继续；程序不自动重复请求 |
| 连接/证书错误 | 检查网络、远程代理或证书配置；不会关闭TLS校验 |
| 返回重定向 | 核对正确地址；不跟随重定向发送密钥 |
| 非JSON、重复字段或输出不完整 | 未执行该决策；核对模型能力与输出上限 |

高级兼容设置（只有服务说明要求时再调整）：

```powershell
# 服务不接受response_format/text.format参数时可关闭，但返回文本仍须是合法JSON。
python -m graph_research model setup --json-mode off

# Chat接口的输出上限字段按服务实际要求明确选择，不自动换协议重试。
python -m graph_research model setup --chat-token-field max_completion_tokens

# 为正式模型调用配置输出上限与超时；0表示不指定输出上限。
python -m graph_research model setup --max-output-tokens 4096 --timeout 90
```

## 与主 agent 共同使用

主 agent 已能拆解固定工具任务时，使用 [MCP](MCP.md)，无需再配置本助手的模型API。只有显式启用内部自主规划时才需要本页配置。

兼容性测试使用过模拟HTTP；是否支持你选择的服务，应通过显式连接测试和已知答案算例核对，不能仅因协议名称一致就宣称全部兼容。
